# Roadmap VPN-Orbit

Цель разработки — [VPN-Orbit v2.0.0](specification.md) для принятия действующей VPN-инфраструктуры. Основной сценарий проходит от инвентаризации до явно разрешённого обслуживания поддерживаемых установок.

## Текущее состояние

- Опубликован [v1.0.0](https://github.com/RoyMan810/VPN-Orbit/releases/tag/v1.0.0). Поддерживаются подготовленные VPS, SSH-наблюдение, аудит, типизированный firewall и ограниченный тестовый перезапуск Docker. Заранее подготовленные профили Remnawave и Bedolaga поддерживают установку, запуск и удаление с сохранением данных.
- В main после v1.0.0 есть копии и восстановление Controller и приложений, диагностика, управление SSH-ключами и подписанное обновление Controller. Результаты и статус публикации указаны в разделе [v1.1.0](#p0--v110-безопасная-эксплуатация-контроллера).
- Начат переход на Mantine. Карточка VPS показывает Compose-проекты и сервисы, подтверждённые в разрешённой области SSH-наблюдения, с отметкой об устаревших результатах. Предпросмотр принятия по свежему снимку Compose показывает сверку образов и состава сервисов с каталогом и метки сетей и томов. Стендовая приёмка инвентаризации и выполнение принятия остаются открытыми.

## Приоритеты v2.0.0

| Порядок | Работа | Статус и проверка |
| --- | --- | --- |
| 1 | Аудит main, контракт сохранения функций, выбор стека | Исходный аудит завершён. [Контракт и архитектура](specification.md) зафиксированы. |
| 2 | Ограниченная инвентаризация существующей инфраструктуры | По явному включению VPS обнаруживаются контейнеры с метками Compose, локальные ID образов, подключённые Docker-сети и тома. Для Nginx на хосте видно состояние службы systemd. Для явно заданных имён доступны проверка локального TLS и срок действия сертификата. CLI сопоставляет DNS и проверяет TLS с внешнего хоста на заданных IP. CLI извлекает точные DNS-имена HTTP-виртуальных хостов из предоставленных конфигураций Nginx. SSH-наблюдение собирает точные имена из списка файлов Nginx, заданного администратором на VPS. По явному включению видны базовые цепочки nftables. Карточка выделяет сети и тома, общие для нескольких проектов Compose на одной VPS. Отдельно видны заданные администратором межсерверные связи. Остаётся подтвердить их работоспособность, охват и отсутствие изменений на двух тестовых VPS с внешними установками. |
| 3 | Подключение из WebUI и подготовка VPS | Мастер запускает подготовку наблюдения утверждённой VPS и показывает этапы вплоть до проверки обоих SSH-входов. Проверка готовности показывает маршруты по умолчанию и наличие Docker CLI и системного плагина Compose. После подтверждённой записи подготовку можно возобновить через консоль контроллера. Сценарий API → Worker → Debian 13 OpenSSH покрыт в [CI](../tests/lab/debian_preparation.py). Для чистой установки Controller на Debian 13 добавлен [сквозной VM-сценарий](../tests/lab/bootstrap-debian-vm.sh) с Docker, HTTPS, входом Owner и аудитом. |
| 4 | Явное принятие и штатные операции | Owner может открыть [предпросмотр принятия](vps.md#наблюдение-и-аудит) по свежему снимку с привязкой к ревизиям VPS и политики. Предпросмотр сверяет digest и состав сервисов с каталогом, показывает метки и прямые подключения к сетям и именованным томам, в том числе у контейнеров вне Compose. Предпросмотр отмечает разные метки конфигурации реплик и bind mounts. До принятия остаётся подтвердить исходные файлы конфигурации, зависимости и исключительное владение ресурсами. Owner может сверить точный просмотренный снимок с текущим инвентарём. Реализовать подтверждение Owner, проверку дрейфа на VPS непосредственно перед изменениями, сохранение данных, откат и сверку потери ответа. Использовать общие сценарии для новых и принятых установок. |
| 5 | Конфигурации, интеграции и обслуживание | Реализовать историю и diff, обновления приложений, Remnawave/Bedolaga API, webhook, безопасное управление HTTPS/firewall и мониторинг. Проверить VPN-маршрут, сроки TLS, оповещения и сохранность SSH-доступа. |
| 6 | WebUI Mantine, обновление и восстановление | Переносить интерфейс вместе со сценариями. Проверить RU/EN, темы, клавиатуру, прогресс, безопасное обновление и восстановление на другом хосте. |
| 7 | Аудиты, стенд и выпуск | Промежуточный и независимый финальный аудит Astra, исправления, сквозные испытания, зелёный CI точного релизного коммита и доверенная подпись. |

Отложены массовые операции, API создания VPS/DNS и универсальные шаблоны Compose. Для принятия K‑VPN достаточно подтверждённых ресурсов на нескольких VPS и каталога поддерживаемых приложений.

## P0 — v1.1.0: безопасная эксплуатация контроллера

Исходники v1.1.0 находятся в main. Публичный релиз и подписанный комплект издателя пока отсутствуют.

- На прежнем кандидате прошли [переход и отказы](https://github.com/RoyMan810/VPN-Orbit/actions/runs/45451124028), [восстановление Controller на двух хостах](https://github.com/RoyMan810/VPN-Orbit/actions/runs/45451129129) и [восстановление данных приложений](https://github.com/RoyMan810/VPN-Orbit/actions/runs/45451115124).
- На отдельной тестовой VPS проверено восстановление Panel, Bot и Cabinet под новыми ID. Подтверждены PostgreSQL, Redis, загрузки, прежний API-ключ Remnawave, Bot → Panel по TLS, маршруты Cabinet и свежий Telegram `/start` в режиме polling.
- [Прогон обновления исходников v1.1.0](https://github.com/RoyMan810/VPN-Orbit/actions/runs/45480389333) завершился ошибкой при подготовке тестовых данных. Прежние прогоны подтверждают лабораторный сценарий на своих коммитах. Для выпуска нужен успешный прогон на точном релизном коммите.

Порядок действий описан в [руководстве по обновлению и восстановлению](operations.md) и [документации по копиям приложений](applications.md#полная-копия-установки).
