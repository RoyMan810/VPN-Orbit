# Установка контроллера

[Документация](README.md)

## Требования

- Чистый сервер amd64 с systemd, Git и правами `sudo`. Для тега `v1.0.0` используйте Ubuntu Server 24.04 или 26.04. Ветка `main` также поддерживает Debian 13 (trixie). CI запускает чистую установку в VM с Ubuntu 24.04 и Debian 13.
- Интернет для загрузки пакетов, исходников, зависимостей и базового образа. Рекомендуются 2 ГиБ RAM и 6 ГиБ в `/var/lib`.
- Если Docker уже установлен, нужен rootful Engine 29.x, Compose v2 или v5 и Buildx. Установщик не удаляет конфликтующие пакеты или существующий VPN-Orbit.
- `/opt`, `/etc`, `/var/lib`, `/run` и их родительские каталоги должны принадлежать root и быть закрыты для записи группы и остальных пользователей. Установщик не исправляет чужие системные права.

## Установка из релиза

`./install` предназначен для чистой машины. Для работающего контроллера на `v1.0.0` описан [переход на v1.1.0](operations.md#переход-с-v100); не применяйте его до публикации доверенного релизного комплекта.

Если контроллер должен управлять VPS, [подготовьте их заранее](vps.md#подготовка-vps). Для публичного HTTPS также заранее подготовьте сертификат.

```sh
git clone --branch v1.0.0 https://github.com/RoyMan810/VPN-Orbit.git
sudo ./VPN-Orbit/install
```

Используйте полный Git checkout тега без изменений отслеживаемых файлов, не архив исходников. Установщик при необходимости ставит Docker, собирает Python 3.15.2 и WebUI. API и Worker работают через Compose, Broker и Supervisor — через systemd. Выделенный Nginx обслуживает HTTPS; API остаётся на `127.0.0.1:18080`.

При локальной сборке root проверяет SHA-256 манифеста и всех файлов комплекта. Это не подпись издателя: вы доверяете выбранному checkout. Внешний комплект использует отдельную проверку Ed25519.

При установке в терминале задайте пароль владельца; минимум 14 символов. Чтобы выбрать имя, передайте `--owner ИМЯ`. Если установка шла без терминала или пароль не был задан, создайте владельца локально ровно один раз:

```sh
sudo /opt/vpn-orbit/admin create-owner --username admin
```

Пользователь в браузере не может создать первого владельца. Пароль не передаётся в аргументах или переменных окружения.

Для проверки установки на чистой Debian 13 используйте полный Git checkout ветки `main` и ту же команду `sudo ./VPN-Orbit/install`.

## Доступ через SSH-туннель

По умолчанию Nginx слушает только `127.0.0.1:18443`. На рабочей машине, используя проверенный SSH-доступ к контроллеру, скопируйте **публичный** локальный CA и добавьте его в хранилище доверия браузера. Затем запустите туннель:

```sh
scp ubuntu@CONTROLLER:/opt/vpn-orbit-bootstrap/web-ca.pem .
ssh -N -L 127.0.0.1:18443:127.0.0.1:18443 ubuntu@CONTROLLER
```

Подставьте свой SSH-логин и адрес. Не отключайте проверку TLS. Откройте [https://127.0.0.1:18443](https://127.0.0.1:18443) и войдите как владелец. Локальный серверный сертификат действует 397 дней.

## Публичный HTTPS

Направьте A-запись домена на контроллер. В примере TCP 80 и 443 свободны; Certbot доступен извне на TCP 80 для выпуска и продления. Замените `orbit.example.org` своим доменом.

```sh
sudo apt install certbot
sudo certbot certonly --standalone --cert-name orbit.example.org -d orbit.example.org \
  --deploy-hook 'systemctl try-restart vpn-orbit-web.service'
sudo ./VPN-Orbit/install --public-domain orbit.example.org
```

Установщик проверит сертификат и ключ до установки. Nginx будет слушать IPv4 TCP 443; командой `--deploy-hook` Certbot перечитывает сертификат после продления через перезапуск выделенной службы. Занятые порты или свой reverse proxy требуют отдельной настройки; bootstrap не переписывает чужую конфигурацию.

## Ручная установка из подписанного комплекта

Этот вариант для администратора, который сам готовит Docker, Compose, Buildx и доверенный host Python 3.15 с SQLite ≥3.45. Требуются systemd и OpenSSL 3. Для обычной установки достаточно `./install`.

На доверенной машине сборки используйте зафиксированный релизный checkout, проверенный OCI digest Python-образа и [официальный age](../tools/fetch_age.py) v1.3.2 linux/amd64. Ключ подписи — отдельный 32-байтный Ed25519 seed, который не копируется на контроллер. Публичный ключ в raw-формате доставьте независимо; файл должен принадлежать root и быть защищён от записи группы и остальных пользователей.

```sh
python3.15 deploy/build_bundle.py --output /path/vpn-orbit-bundle \
  --signing-key /offline/release-signing.seed \
  --python-image "$PYTHON_IMAGE" --age-tool /verified/age/age
sudo /trusted/python3.15 deploy/installer.py install \
  --bundle /path/vpn-orbit-bundle --trust-key /etc/vpn-orbit-release.pub \
  --origin https://orbit.example.org --port 18080 --check
```

Для сборки комплекта Debian 13 передайте `--platform debian-13-amd64`. По умолчанию собирается комплект для Ubuntu. Установка проверяет соответствие платформы хоста подписанному манифесту.

`--check` проверяет комплект и предварительные условия, не устанавливая контроллер. Для свежей установки уберите `--check`; при необходимости добавьте `--targets /root/approved-targets.json --web-enrollment`. Для релизной версии `--development` не нужен. Внешний комплект не заменяет развёртывание HTTPS и статики: [сборка и публикация WebUI](../web/README.md).

Для комплекта **обновления** добавьте `--include-web` и используйте Node.js 26. Сверьте версию и `source_commit` проверенного `manifest.json` с точным принятым коммитом перед публикацией. Собирайте ключом издателя, не тестовым ключом CI; распространяйте открытый ключ и его SHA-256 по независимому доверенному каналу.

## Если установка прервалась

При сбое до начала установки исправьте причину (например, доступ к registry или занятый порт) и повторите команду. Если уже создано состояние в `/opt/vpn-orbit`, проверьте `install-state.json` и [журналы](operations.md#контроллер-и-https). Повторный запуск не стирает состояние. Не удаляйте каталоги и ключи ради повторной установки: эта версия не переносит старую БД и не восстанавливает контроллер из копии.
