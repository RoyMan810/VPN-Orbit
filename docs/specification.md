# Техническое задание VPN-Orbit v2.0.0

VPN-Orbit управляет существующей VPN-инфраструктурой на VPS. Первый сценарий — подключить распределённую установку с Remnawave Panel/Node, Bedolaga Bot/Cabinet, Docker Compose и Nginx. VPN-конфигурация, данные и действующие связи сервисов сохраняются при принятии. Исходная точка для Controller v2.0.0 — чистая установка. Поддержка версий и перенос внутренней базы Controller до v2.0.0 не входят в требования. План реализации и фактический статус ведутся в [Roadmap](roadmap.md).

## Сценарии и приёмка

| Сценарий | Критерий приёмки |
| --- | --- |
| Установка Controller | Чистые Ubuntu Server 24.04/26.04 LTS и Debian 13 на amd64. Через установщик создаётся Owner и настраивается HTTPS. Работают диагностика, обслуживание и аварийное восстановление с консоли. |
| Подключение VPS | Owner вводит IP, логин, пароль или SSH-ключ и при необходимости порт. До передачи учётных данных Controller сверяет отпечаток хоста с доверенным значением. Учётные данные для подготовки удаляются после использования по умолчанию. |
| Подготовка VPS | Controller показывает проверки ОС, полномочий, сети, Docker/Compose и конфликтов. Подготовка создаёт ограниченный доступ, допускает безопасное возобновление и сохраняет существующий административный доступ. Первый осмотр существующей установки выполняется до изменений. |
| Инвентаризация и принятие | Просмотр охватывает Compose, контейнеры, тома, сети, Nginx, DNS/TLS, firewall и связи приложений. В отчёте видны охват, время, ограничения и конфликты. Принятие подтверждается Owner для конкретного хоста, ресурсов и ревизии конфигурации. Неоднозначное владение, изменившийся снимок и несовместимые ресурсы блокируют изменение. |
| Приложения и интеграции | Новые и принятые установки используют общие операции установки, запуска, остановки, перезапуска, обновления, резервного копирования, восстановления и удаления в пределах возможностей профиля. Разрешённые конфигурации имеют валидацию, diff, историю и проверяемый возврат. Официальные API Remnawave и Bedolaga используются для поддерживаемых интеграций и webhook. Проверяются Panel ↔ Node, Bot ↔ Panel, Cabinet и межсерверный VPN-маршрут на тестовом стенде. |
| HTTPS и firewall | Управляются только утверждённые Nginx-маршруты и правила. Проверяются DNS, сертификат, автоматическое продление и доступность через новое SSH-соединение. Неудачная проверка опасного изменения запускает независимый откат. |
| Наблюдаемость | В WebUI доступны время и актуальность наблюдений, CPU/RAM/диск/сеть, состояние Docker и приложений, ошибки DNS/TCP/TLS и срок сертификата. Критические уведомления поступают с подавлением дубликатов. |
| Резервные копии и обновления | Зашифрованные копии Controller и поддерживаемых приложений восстанавливаются на другом хосте с проверкой работоспособности и данных. Обновление Controller проверяет доверенную подпись и целостность, создаёт копию и имеет путь восстановления или отката. |
| WebUI | Интерфейс Mantine поддерживает тёмную тему, RU/EN, клавиатуру, активные операции и понятные состояния загрузки, ошибок и устаревших данных. Для опасных действий виден предмет подтверждения. |

## Архитектура

- **Controller.** Python, FastAPI/Pydantic, SQLite и AsyncSSH. Организация по сценариям сервера, приложений, операций и обслуживания. Один набор исходников с отдельными Unix UID и узкими интерфейсами API, Worker, Broker и Authority. Одна долговечная очередь хранит состояние операций и журнал. У каждого удалённого эффекта есть тип, цель, проверяемый исход и read-only сверка при потере ответа.
- **Удалённый доступ.** Bootstrap использует проверенный административный SSH для подготовки. Для повседневного наблюдения и типизированных операций используются ограниченные SSH-учётные записи и защищённые helper-команды. Browser API получает безопасные метаданные, секреты остаются в Vault либо на хосте. Метки Docker помогают установить состав проекта. Полномочия выдаются по утверждённому снимку с проверкой принадлежности, зависимостей и расхождений.
- **WebUI.** TypeScript, React, Vite и Mantine. Сценарии переводятся по мере реализации, включая проверки CSP, обеих локализаций и клавиатурного управления. Существующая статическая публикация через Nginx подходит для same-origin API.
- **Эксплуатация.** Nginx и ACME обслуживают выделенные маршруты. Для резервного копирования используются существующие age, SQLite Online Backup и логические снимки PostgreSQL. Для начального мониторинга достаточно периодических ограниченных наблюдений с хранением времени и результата.

Go упростил бы доставку API одним бинарником. Перенос существующего SSH-протокола, очереди, аудита и механизмов восстановления увеличил бы риск регрессий. PostgreSQL и отдельный брокер потребовали бы сопровождения дополнительных сервисов при одном Controller. Ansible требует отдельного runtime и модели полномочий для задач подготовки. Текущие реализации проверяются и перерабатываются по границам сценариев.

## Выпуск

Доказательства включают модульные, интеграционные и браузерные проверки, системные тесты на одноразовых VM и сквозную приёмку минимум на двух разрешённых тестовых VPS. Проверяются обе ОС, потеря соединения, повтор подготовки, дрейф, общие ресурсы, блокировка недопустимого эффекта, восстановление на другом хосте и работа приложений после восстановления. Промежуточный и финальный аудит выполняет Astra. Выпуск требует зелёных проверок точного релизного коммита, доверенной подписи артефактов и устранения блокирующих замечаний. Работа с действующей K-VPN требует отдельного разрешения.
